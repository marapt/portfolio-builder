# Mara Martins Portfolio - Agile Scrum Protocol

This document establishes the formal operating procedures for the management and development of the Mara Martins portfolio. Adherence to these protocols ensures transparency, speed, and enterprise-grade program management.

## 📋 Core Protocols

### 1. The Verification Rule
- **Description**: No task shall be transitioned to "Done" without programmatic verification.
- **Enforcement**: Status updates must be confirmed via a Jira API check and, where applicable, a live UI verification via browser tooling.
- **Goal**: 100% accuracy between the development environment and the live stakeholder dashboard.

### 2. The Agile Sprint-Handover Rule
- **Description**: Sprints must be managed with a "Zero-Lag" policy.
- **Enforcement**: Upon the closure of a Sprint, the subsequent Sprint in the backlog must be started immediately. All remaining "In Progress" or "Blocked" tasks from the closed sprint must be migrated to the new active sprint or moved to the top of the backlog.
- **Goal**: Maintain continuous development momentum and consistent Sprint reporting.

### 3. Documentation Rule (Reflections)
- **Description**: Architectural learnings, build failures, and UI optimizations must be documented in the `Reflections.md` log.
- **Enforcement**: At the end of each major feature branch or sprint closure, the AI assistant must append "Learnings" to the log.
- **Goal**: Build a knowledge base for future maintenance and proof of work for recruiters.
